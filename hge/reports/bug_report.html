BUG-001 Medium • Severity 3
Storefront Product Stock Counter in UI DOM is Not Decremented Upon Successful Order
Affected Test: 01-storefront-checkout.spec.ts › TC-SF-01
Description: When an order is placed on the Storefront, the in-memory JavaScript database updates prod.stock -= qty, but the DOM element displaying remaining inventory (e.g. #prod-stock-1) is not re-rendered. The UI continues to display "In Stock: 15 units" instead of 14 units.
// In handleUiCheckout(): if (prod) prod.stock -= qty; // Updated in memory // Defect: Missing DOM update -> document.getElementById('prod-stock-' + prod.id).innerText = `In Stock: ${prod.stock} units`;
Suggested Fix: Invoke a reactive re-render function (e.g., renderProductCards()) in handleUiCheckout() so the inventory counter visually updates on the user interface.
BUG-002 Critical / High • Severity 1
EU VAT Reverse Charge B2B Exemption Fails for Valid VAT Numbers Due to Regex Casing & Unescaped Pattern
Affected Test: 01-storefront-checkout.spec.ts › TC-SF-07
Description: Valid EU VAT numbers (e.g. HU12345678, DE987654321) always trigger "❌ Invalid EU VAT syntax", preventing B2B customers from ever receiving 0% Reverse Charge tax exemption.
// In validateVatNumber(): const val = document.getElementById('ui-vat-number').value.trim().toUpperCase(); if (/^(HU|DE|AT|FR)d{8,9}$/.test(val)) { // Defect: 'd' instead of '\d', and no /i flag with uppercase string
Suggested Fix: Replace regex with /^(HU|DE|AT|FR)\d{8,9}$/ in validateVatNumber() to properly match 8-9 digits following the 2-letter country code.
BUG-003 High • Severity 2
SQL Workbench SELECT Query Engine Fails to Parse Queries Due to Missing Whitespace Escape in Regex
Affected Test: 06-sql-and-integrity.spec.ts › TC-INT-01
Description: Standard queries such as SELECT * FROM orders; fail to match the query dispatcher and fall through to default fallback: "Query executed against in-memory tables." The table of results is never rendered.
// In executeSqlQuery(): if (/^SELECTs+/i.test(clean)) { // Defect: 'SELECTs+' literally matches 'SELECTs' rather than whitespace '\s+'
Suggested Fix: Update regex to /^SELECT\s+/i and all child table matchers to /FROM\s+orders/i.
BUG-004 High • Severity 2
SQL Workbench UPDATE Mutation Query Does Not Execute Due to Malformed Regex Dispatcher
Affected Test: 06-sql-and-integrity.spec.ts › TC-INT-02
Description: Clicking the chip query "Force Refund (ID 101)" sets UPDATE orders SET status = 'REFUNDED' WHERE id = 101;, but does not update the database record because the regex dispatcher requires a literal 's' rather than a space.
