2. Bug / Defect Report

Discovered during E2E Execution on https://testacademy.hu/qa-lab/e2e-app
DEFECTS FOUND: 8

The automated tests were executed strictly against business and security specifications without patching or modifying assertions to pass. The following 8 authentic software defects were detected in the client application:

BUG-001 Medium • Severity 3
Storefront Product Stock Counter in UI DOM is Not Decremented Upon Successful Order
Affected Test: 01-storefront-checkout.spec.ts › TC-SF-01
Description: When an order is placed on the Storefront, the in-memory JavaScript database updates prod.stock -= qty, but the DOM element displaying remaining inventory (e.g. #prod-stock-1) is not re-rendered. The UI continues to display "In Stock: 15 units" instead of 14 units.
Suggested Fix: Invoke a reactive re-render function (e.g., renderProductCards()) in handleUiCheckout() so the inventory counter visually updates on the user interface.
BUG-002 Critical / High • Severity 1
EU VAT Reverse Charge B2B Exemption Fails for Valid VAT Numbers Due to Regex Casing & Unescaped Pattern
Affected Test: 01-storefront-checkout.spec.ts › TC-SF-07
Description: Valid EU VAT numbers (e.g. HU12345678, DE987654321) always trigger "❌ Invalid EU VAT syntax", preventing B2B customers from ever receiving 0% Reverse Charge tax exemption.
Suggested Fix: Replace regex with /^(HU|DE|AT|FR)\d{8,9}$/ in validateVatNumber() to properly match 8-9 digits following the 2-letter country code.
BUG-003 High • Severity 2
SQL Workbench SELECT Query Engine Fails to Parse Queries Due to Missing Whitespace Escape in Regex
Affected Test: 06-sql-and-integrity.spec.ts › TC-INT-01
Description: Standard queries such as SELECT * FROM orders; fail to match the query dispatcher and fall through to default fallback: "Query executed against in-memory tables." The table of results is never rendered.
Suggested Fix: Update regex to /^SELECT\s+/i and all child table matchers to /FROM\s+orders/i.
BUG-004 High • Severity 2
SQL Workbench UPDATE Mutation Query Does Not Execute Due to Malformed Regex Dispatcher
Affected Test: 06-sql-and-integrity.spec.ts › TC-INT-02
Description: Clicking the chip query "Force Refund (ID 101)" sets UPDATE orders SET status = 'REFUNDED' WHERE id = 101;, but does not update the database record because the regex dispatcher requires a literal 's' rather than a space.
Suggested Fix: Update regex to /^UPDATE\s+orders/i and ID capture to /id\s*=\s*(\d+)/i.
BUG-005 Medium • Severity 3
SQL Workbench "Audit Trail" Chip Fails to Display Generated Audit Log Records
Affected Test: 06-sql-and-integrity.spec.ts › TC-INT-03
Description: Order placement successfully writes a record into DB.audit_logs, but querying the table via chip SELECT * FROM audit_logs ORDER BY id DESC; falls through without rendering rows due to /FROMs+audit_logs/ regex pattern failure.
Suggested Fix: Fix the table regex selector to /FROM\s+audit_logs/i in executeSqlQuery().
BUG-006 Medium • Severity 3
Storefront Subscription Quantity Input Lacks "required" Attribute, Allowing Silent Fallback to 1 Unit
Affected Test: 07-tc-02a-empty-fields.spec.ts › TC-02A.3
Description: The ui-qty number input has min="1" max="100", but lacks the HTML5 required attribute. When a customer clears the quantity input, the browser treats it as valid (validity.valid === true), and the JavaScript fallback parseInt(...) || 1 silently orders 1 unit instead of prompting the user for required input.
Suggested Fix: Add the required attribute to the input element: <input type="number" id="ui-qty" ... required>.
BUG-007 Critical / High • Severity 1 (OWASP A08)
Client-Side DOM Parameter Tampering: Storefront Trusts Client DOM Element For Financial Order Total
Affected Test: 10-security-owasp.spec.ts › TC-SEC-04
Description: The application takes the transaction order total directly from the client-side DOM text element #ui-sum-total instead of calculating/validating it server-side. An attacker modifying the DOM innerText to $0.01 submits orders charged at $1, bypassing product catalog pricing.
Suggested Fix: Never trust client DOM prices. Compute item prices, discounts, and VAT strictly in application/server business logic before saving orders.
BUG-008 High • Severity 2 (OWASP A04 / CWE-362)
Missing Button Debounce & Double Submission Allows Duplicate Transaction Generation
Affected Test: 10-security-owasp.spec.ts › TC-SEC-05
Description: The checkout submit button #btn-ui-submit is not immediately disabled upon being clicked. A rapid double-click creates two identical duplicate orders in the database for the exact same purchase attempt.
Suggested Fix: Immediately disable the button upon click (button.disabled = true) until transaction completes, and implement idempotency keys for client-server requests.
